# ncm2mp3 —— 网易云 NCM 转换器（Windows 桌面版 + Android 版）

把网易云音乐下载的 `.ncm` 文件还原成普通音频文件，**不重新编码、音质保持原样**：

| 源文件里的音频 | 转换结果 |
| --- | --- |
| MP3（例如 320 kbps） | `.mp3`，仍是 320 kbps |
| 无损 FLAC（例如 96 kHz/24 bit） | `.flac`，仍是原来的无损数据 |

也就是说：**是 MP3 就还是 MP3，不是 MP3 就保持原格式**，只做解密 + 补上标题/歌手/专辑/封面标签。

> **Android 版**在 [`android/`](android/) 目录：`dist\ncm2mp3-android.apk`（45 MB，Flutter 写的，
> 与 Windows 版同一套算法、同样的跳过与自检逻辑）。安装使用说明见 [android/README.md](android/README.md)。

## 一、快速开始

**方式 A（最简单，免安装）**：双击 **`dist\ncm2mp3.exe`**。
这是一个自带 Python 运行时的独立程序（约 13 MB），电脑上**不用装任何东西**，官方解码库也已经打包在里面。

> 如果 Windows 弹出「已保护你的电脑」或杀毒软件误报，那是因为这个 exe 是打包生成的、没有数字签名。
> 点「更多信息 → 仍要运行」即可；不想冒险就改用方式 B。

**方式 B**：双击 **`启动 ncm2mp3.bat`**（需要电脑上有 Python 3.8+，脚本会自动去找）。
- 提示找不到 Python：去 <https://www.python.org/downloads/windows/> 装一个，安装时**勾选 “Add python.exe to PATH”**，装完再双击即可。
- 排查问题请双击 **`启动 ncm2mp3（带控制台）.bat`**，报错信息会留在窗口里。

然后界面上按 ①②③ 走：
   - **① 选择目录**：选中放着 ncm 的目录（例如 `G:\Music\网易云`），点「扫描 ncm」。子目录会一并扫描。
   - **勾选文件**：单击最左侧的方框即可勾选/取消，也可以双击整行；上方有「全选 / 全不选 / 反选」。
   - **② 输出设置**：默认输出到**源文件所在目录**；想换个地方就点「浏览…」。常用选项都在这一栏。
   - **③ 开始转换**：点「▶ 开始转换」，下面有总进度、当前文件进度、逐文件状态和日志，随时可以「■ 停止」。
3. 转换完成后可以直接点「打开输出目录」。想收拾同一首歌的多个副本，点 **🧹 清理重复音乐**（见第五节）。

程序会记住上次的设置（存在同目录的 `config.json`）。

## 二、命令行用法（批处理/自动化）

打包版：`dist\ncm2mp3-cli.exe`；源码版：`python cli.py`。

```bat
ncm2mp3-cli.exe scan "G:\Music\网易云"
ncm2mp3-cli.exe convert "G:\Music\网易云" -o "D:\Music-out" --jobs 4
ncm2mp3-cli.exe convert a.ncm b.ncm --overwrite --delete-source
```

常用参数：

| 参数 | 含义 |
| --- | --- |
| `-o, --output` | 输出目录（默认与源文件同目录） |
| `--flat` | 输出目录下不保留子目录结构 |
| `--artist-folder` | 直接放在源目录的歌，按歌手归入子目录 |
| `--rename` | 用「歌手 - 歌名」命名（默认沿用原文件名） |
| `--overwrite` | 覆盖同名文件（默认跳过） |
| `--delete-source` | 成功后删除原 ncm |
| `--no-tags` | 不写标签与封面 |
| `--cover` | 另外把封面导出成图片 |
| `--no-verify` | 跳过转换后自检 |
| `--jobs N` | 并发线程数（默认 4） |
| `--engine builtin\|official` | 转换引擎，见下文 |
| `--limit N` | 只处理前 N 个（试跑） |

## 三、两种转换引擎

| | 内置引擎（默认） | 官方引擎 |
| --- | --- | --- |
| 实现 | 本项目用 Python 标准库实现 | 调用上游 [taurusxin/ncmdump](https://github.com/taurusxin/ncmdump) 发布的 `libncmdump.dll` |
| 依赖 | 无（不需要装任何包） | 需要 `vendor\libncmdump\libncmdump.dll` |
| 进度/停止 | 每个文件实时进度，可随时停止 | 只能整文件完成，不能中途停 |
| 标签 | 本项目写（MP3 用 ID3v2.3，FLAC 用 Vorbis Comment + PICTURE） | 由官方代码（taglib）写 |
| 转换后自检 | 有 | 有 |

**两种引擎输出的音频正文逐字节相同**（已用官方 exe 交叉验证，见下）。

## 四、已经转换过的文件会自动跳过

这是默认行为：转换时如果发现**目标位置已经有这首歌的成品**，就记「已跳过」，既不重复转、也绝不覆盖。

判定范围（未勾选「覆盖已存在文件」时）：

* 目标目录里存在完全同名的文件；
* 目标目录里存在**文件名相同、只是音频后缀不同**的成品（例如之前用别的工具转成过 `.mp3`，而这次源文件是无损 `.flac`）。

界面上扫描完会直接把这类文件标成「已存在，将跳过」，顶部显示「其中 N 个已有转换结果，将自动跳过」；命令行下逐条打印「↷ 已有转换结果（xxx.flac），已跳过」。

### 配套的两个设置

| 设置 | 作用 |
| --- | --- |
| 保留子目录结构 | 输出目录下按源目录的相对路径建子文件夹：`VipSongsDownload\五月天\a.ncm` → `<输出目录>\五月天\a.flac` |
| 直接放在源目录的歌按歌手归档 | 那些没有子目录、直接躺在扫描根目录里的歌，按第一位歌手归入子目录（多歌手取第一位），避免散落在输出目录根部 |

两个选项合起来，「源目录 = 下载目录、输出目录 = 音乐库根目录」这种布局就能一直保持整齐，反复运行只会补转新增的歌。

### 实测（对 `G:\Music\网易云` 连续跑六次，期间一直在下载新歌）

| 运行 | 结果 |
| --- | --- |
| 第 1 次 | 成功 240 / 跳过 0 / 失败 0，用时 216.6s |
| 第 2 次 | 成功 38 / **跳过 235** / 失败 0，用时 44.7s |
| 第 3 次 | 成功 29 / **跳过 273** / 失败 0，用时 41.1s |
| 第 4 次 | 成功 22 / **跳过 302** / 失败 0，用时 35.5s |
| 第 5 次 | 成功 15 / **跳过 324** / 失败 0，用时 30.7s |
| 第 6 次 | 成功 8 / **跳过 339** / 失败 0，用时 26.7s |

累计转出 352 首、0 失败；从第 2 次起，`赵雷 - 成都.ncm`、`五月天 - 倔强.ncm` 这类已转过的文件全部命中「已有转换结果，已跳过」。

## 五、清理重复音乐

主界面上的 **🧹 清理重复音乐** 按钮，用来收拾同一首歌的多个副本（网易云重复下载会产生 `歌名 (1).ncm` 这种文件）。命令行等价写法：

```bat
ncm2mp3-cli.exe dedup "G:\Music\网易云"                :: 只扫描预演，不动任何文件
ncm2mp3-cli.exe dedup "G:\Music\网易云" --apply        :: 确认后执行（移入回收站）
ncm2mp3-cli.exe dedup "G:\Music\网易云" --apply --all  :: 连非默认类别一起处理
```

**判定方式**（先扫描预览，再由你逐组勾选确认）：

| 类别 | 判定依据 | 默认 |
| --- | --- | --- |
| 同名重复（内容相同） | 同目录，文件名去掉 `(1)`／`（2）`／`- 副本` 后相同，且**音频正文 sha256 完全相同** | ✔ 勾选 |
| 同名重复（内容不同） | 文件名相同但音频内容不同（不同版本/不同码率） | 不勾选 |
| 同曲不同格式 | 同名但后缀不同（flac + mp3） | 不勾选（保留无损那份） |
| 跨目录同名 | 不同目录下的同名歌曲 | 不勾选 |

安全设计：

* **先看清单再动手**：扫描只读，不动文件；删除前还要再确认一次；
* **每一组至少保留一个文件**，永远不会出现「整组删光」；
* 删除走 **Windows 回收站**，随时可以还原，不做硬删除；
* 音频内容不同的同名文件绝不默认选中；
* 界面上的「只选『内容相同』」按钮可一键回到最保守的选择。

实测：对 `G:\Music\网易云` 扫描到 75 组疑似重复，其中**默认勾选的「内容相同」70 组、可释放 6.7 GB**，全部是音频正文逐字节相同的 `(1)` 副本；其余几组（跨目录同名等）只做提示、不默认选中。（上面这次是命令行预演模式，没有删除任何文件。）

## 六、正确性验证（本项目是怎么证明自己没转坏的）

### 1. 与官方实现逐字节比对

`tools\crosscheck.py` 会把同一个 ncm 分别交给本项目和官方 `ncmdump.exe`，剥掉各自的标签区后比较音频正文的 sha256：

```bat
python tools\crosscheck.py vendor\ncmdump\ncmdump.exe ^
    "G:\Music\网易云\VipSongsDownload\赵雷 - 成都.ncm" ^
    "G:\Music\网易云\VipSongsDownload\赵雷\赵雷 - 不开的唇.ncm"
```

实测结果（4/4 完全一致）：

| 文件 | 类型 | 音频正文大小 | sha256 前 24 位 | 结论 |
| --- | --- | --- | --- | --- |
| 赵雷 - 成都.ncm | mp3 | 13,137,629 B | `15933cfe61a88cd454dab2ff…` | ✔ 一致 |
| 赵雷 - 我记得.ncm | mp3 | 13,198,233 B | `b391b37803ebc9cd5003bb0f…` | ✔ 一致 |
| 赵雷 - 不开的唇.ncm | flac | 84,598,122 B | `b81ea656554d285716a8f29f…` | ✔ 一致 |
| 赵雷 - 十九岁.ncm | flac | 84,349,097 B | `9d46d9be7ab8ecd4b67d3053…` | ✔ 一致 |

### 2. 转换后自检（每次转换都会跑两件事）

**第一件：结构是否正常**

* FLAC：解析 STREAMINFO（采样率/声道/位深/总采样数）并检查音频区首个帧同步码；
* MP3：从第一个同步字开始走完整条帧链，报告帧数、采样率、码率；
* 标签：写完后读回，与元数据比对。

**第二件：源文件本身是不是完整的**

网易云的下载如果中途断掉，ncm 的头部和封面都是好的，只有**音频正文被截断**。这种情况下元数据里写的仍是完整时长，FLAC 的 STREAMINFO 也是从头照抄的，光比对它们发现不了问题。所以自检会真去数一遍帧：

| 格式 | 怎么判断被截断 |
| --- | --- |
| MP3 | 走完所有帧算出**实际时长**，与 ncm 元数据时长比对 |
| FLAC | 逐帧解析帧头（含 CRC-8 校验）累加采样数，与 STREAMINFO 声明的总采样数比对 |

实测：完整文件覆盖 100.0%（3067 帧）不报警；把音频截到 40% 后，mp3 报「实际时长 2:11 与元数据 5:28 不符」、flac 报「实际只覆盖约 42%」。

> ⚠ 自检没过时，**即使勾选了「成功后删除原 ncm」也不会删源文件** —— 宁可留下 ncm，也不能只留一个残缺成品。

### 3. 用系统解码器独立复核

转换出的文件交给 Windows 自己的解码器读取（资源管理器的媒体属性），时长、标题、歌手、专辑均正常 —— 说明文件是标准可播放的，不是“能解密但播不了”。

> 顺带一提：调试期间就是靠这套比对发现并修好了一个真实 bug —— NCM 的密钥块在做完 AES 解密后，**必须去掉最后一块的 PKCS#7 填充字节**，否则生成的密钥流完全不同，解出来的是一整片乱码。细节见 `ncm2mp3/ncm.py` 里的 `aes_ecb_decrypt_unpad()`。

### 4. 其他已验证的边界情况

| 场景 | 结果 |
| --- | --- |
| 非 ncm 文件 / 被截断的 ncm | 干净报错，不崩溃，不留 `.part` 残留；命令行版会明确列出坏文件并返回非 0 |
| **音频被截断的 ncm（下载没下完）** | 转换后自检报 ⚠「源文件很可能没有下载完」，且不删源文件 |
| 目标文件已存在（未勾选覆盖） | 记「已跳过」，不动原文件 |
| 转换前后源 ncm | sha256 完全不变（默认不碰源文件） |
| 转换途中点「停止」 | 6 个大文件全部干净取消，无 `.part`/临时目录残留 |
| 中文路径、中文文件名 | 正常（内置引擎与官方 dll 均通过） |
| 中文 Windows 的 GBK 控制台 | 命令行版正常输出，不再因打印 ✔ 崩溃 |
| 130 MB 无损文件 | 约 1 秒完成（只做异或解密，不做解码/编码） |
| 打包后的 exe | 内置引擎 / 官方引擎产物的音频正文 sha256，与官方 `ncmdump.exe` 完全一致 |

## 八、常见问题

**会不会重新编码、音质变差？**
不会。整个过程只是把 ncm 的加密层剥掉，音频码流一个字节都没改，只是前面补了标签块。无损源文件出来的仍然是无损。

**我有一堆重复文件（`xxx (1).ncm`）怎么办？**
输出文件名默认沿用原文件名，所以不会互相覆盖；要清理重复可以先按「用歌名命名 + 覆盖」跑一遍。

**能把 flac 转成 mp3 吗？**
本工具按你的要求不做重编码。如果哪天需要转 mp3，那属于重新编码（有损），需要额外的编码器。

**转换会不会动我的原文件？**
默认不会。只有显式勾选「成功后删除原 ncm」（或命令行加 `--delete-source`）才会删。中途失败或取消时，半成品会写成 `.part` 并被清理，不会留下损坏文件。另外：**如果转换后自检没通过，即使勾了删除也不会删源文件**。

**有的歌好像没下载完，会不会转出一个残缺文件？**
会转出来，但**自检会报 ⚠ 并在日志里写明**（例如「实际时长 2:11 与元数据 5:28 不符，源文件很可能没有下载完」）。看到这种提示就重新下载那首歌再转。这也正是自检不通过时拒绝删除源文件的原因。

**支持哪些系统？**
Windows 10/11 + Python 3.8 以上（自带 tkinter）。界面是 Python 标准库，不需要安装任何第三方包。
